# Portfolio GitHub Pages

1. Derive the site origin and base path from the approved Pages destination. Check both a root build and a project-subdirectory build with a local server. Visit a case study directly and refresh it.
2. Verify generated navigation, assets, resume paths, canonical URLs, the sitemap, robots.txt, and custom 404 paging under the applicable base.
3. Validate the deployment workflow against current GitHub documentation. Check reproducible install, quality gates, build output, artifact upload, deployment permissions, branch triggers, and concurrency.
4. Report local build and path evidence separately from any deployment evidence. Obtain the owner's authorization before pushing, changing remote settings, or deploying publicly.
