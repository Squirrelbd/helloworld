# Portfolio content

1. Start with the owner's answers and assets. Treat the Git remote as evidence of the checkout destination. Ask the owner before using its account name as a public identity or social link.
2. For each case study, establish the problem, the owner's contribution, hardware and software, the device-to-application data flow, engineering tradeoffs, validation, and outcomes. Confirm the material the owner can publish, including diagrams and company names.
3. Keep unpublished evidence out of site data and static output. Leave unknown facts absent or clearly marked for editorial review. Use confirmed values in resume links, social links, search metadata, and structured data.
4. Hand off approved facts, assets, and open questions so site data can be updated without editing components.
